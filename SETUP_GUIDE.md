# A1 evidence setup

1. Check with your lecturer that the starter files and AI assistance are permitted. Both students should review and edit the documents and understand the code.
2. Create a private GitHub repository named `pet-care-group-3`. Add the other member and lecturer using their actual GitHub usernames.
3. Upload reviewed files, including the hidden `.github/workflows/ci.yml` and `.gitignore`. Commit to main.
4. Create a GitHub project board with To do, In progress, In review and Done. Use `backlog.csv` as a guide to create one issue for each agreed story, with its ID, acceptance criteria, priority and estimate. Link issues to the board. Mark all unstarted items To do.
5. Create a real branch for a small change, such as adding a test for the seven-day boundary. Commit the change and open a pull request against main. The other member should inspect and review the change.
6. On the pull request, wait for the Starter tests check to finish. If it fails, fix it on the branch. When it passes, capture a screenshot of the actual PR with its green check and the Actions run. Do not substitute the local test log for this requirement.
7. Add repository and board URLs and the actual screenshot to the report. Record the real meeting minutes, stakeholder confirmation, contribution details and AI-use statement. Confirm the revised schedule.

The sample setup is not a deployed website or a remote CI result. The starter reminder rule uses a seven-day upcoming window, which the stakeholder must confirm.
